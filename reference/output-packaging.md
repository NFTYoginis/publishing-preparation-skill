# Output packaging

**Source:** `GabeYoga-HQ/Detox Book/Are You Actually Hungry - Final Publishing Versions/README.md` — the packaging README for the fifth book to use this convention, which states outright: *"Same packaging convention as the other four books."* Proven across five shipped books, not one.

---

## The six-file convention

Every finished book, regardless of which pipeline produced it, packages to the same six files:

| File | What it is |
| - | --- |
| `<slug>-front-cover.png` | Front cover, standalone (real example: 1804×2705px) |
| `<slug>-back-cover.png` | Back cover, standalone (real example: 1800×2700px, 6×9in @ 300 DPI) |
| `<slug>.pdf` | The full laid-out book — every chapter, front matter, appendices, infographics, photo openers |
| `<slug>.epub` | **Amazon KDP ebook format** — front cover embedded, chapter TOC. Uploads to KDP directly. |
| `<slug>.docx` | Word version — for Kindle Create or any editor |
| `<slug>.md` | Full manuscript in Markdown, build notes stripped (the real example ran ~41,000 words) |

Plus a packaging README (modeled on the real one above) stating what each file is for, any open items (missing title, missing cover source — see `rules.md`'s empty-input handling), and the book's ISBN status.

## The KDP `.kpf` note

KDP accepts EPUB, DOCX, or `.kpf` for upload. **The `.kpf` format can't be generated by script** — it's made in Amazon's free Kindle Create desktop app: open Kindle Create → import the `.docx` (or the `.epub`) → export. Name this as an available option in the packaging README, not something this specialist builds. The EPUB uploads to KDP as-is without needing the `.kpf` step at all.

## ISBN note

If no ISBN is assigned yet, say so plainly in the packaging README rather than leaving the barcode question implicit — the real precedent README states this directly ("No ISBN barcode included — [book] has no ISBN assigned yet... Add the barcode PNG here once you have it"). ISBN/EAN-13 acquisition itself is operator-only — see `identity.md`'s "What you don't do." See `reference/retail-technical-requirements.md` for barcode placement specs once an ISBN exists.

## Packaging README template

```markdown
# <Book Title> — Final Publishing Versions

<One-line subtitle or description>
<Author name>

Same packaging convention as [prior book(s)]. Source files generated <date>.

| File | What it is |
| --- | --- |
| `<slug>-front-cover.png` | Front cover, standalone (<dimensions>) |
| `<slug>-back-cover.png` | Back cover, standalone (<dimensions>) |
| `<slug>.pdf` | The full laid-out book — <page count> pages, <chapter count> chapters + <front/back matter> |
| `<slug>.epub` | **Amazon KDP ebook format** — front cover embedded, chapter TOC. Upload this to KDP directly. |
| `<slug>.docx` | Word version — for Kindle Create or any editor |
| `<slug>.md` | Full manuscript in Markdown (~<word count> words, build notes stripped) |

## About the Amazon KDP format
KDP accepts **EPUB** (here), **DOCX** (here), or **.kpf**.
The `.kpf` can't be generated by script — open Kindle Create → import the `.docx` (or the EPUB) → export. Otherwise the EPUB uploads to KDP as-is.

## Notes
- <ISBN status — assigned/pending, barcode PNG present or not>
- <Any open items: placeholder title, missing cover source, etc. — per rules.md's empty-input handling>
```
